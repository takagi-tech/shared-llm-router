## 4. 継続する制約と検証方針

- 推論サーバの起動・停止、ツール実行、モデルの自動切替は担当しない。
- 長さの補完・切り詰め、接続後の独自応答期限、自動再送を通常推論へ追加しない。
- Capacityは管理者が設定する。合否判定・推奨値・自動適用は行わない。
- Schedulerは単一の管理主体とし、複数workerに実行枠を分散しない。GuideLLM runnerは試験実行用の別プロセスである。
- 競合・停止・欠測・障害は模擬上流で再現し、実機はモデル固有の挙動と実性能を確認する。テストの成功を未検証環境へ一般化しない。
- 過去の実測結果は測定当時の構成・エンジン・Aliasを維持する。最新の登録設定は管理画面を正とする。
