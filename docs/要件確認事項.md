## 2. 引き続き適用する条件

- 全接続先でtool callingを利用する前提。通常応答・Streamingの両方で、ツール定義、選択指定、呼出しID、名前、引数、ツール結果を保持して中継する。
- Routerはツールを実行しない。ツール実行と結果を含む次のAPI呼出しはクライアントが担当する。
- 長いコンテキストを想定する。Router独自のコンテキスト長や生成長の上限を挿入しない。入力の切り詰め、要約、`max_tokens`等の補完・上書きをしない。省略された値は省略のまま転送し、上流の設定を尊重する。
- 上流のコンテキスト制限に抵触した場合は、内容を変更して再送せずエラーを返す。
- 画像対応は現時点で予定しない。
- 既存利用者は上流へ直接アクセスしている。順次Routerに統合するため、直接アクセスの負荷追跡や統合完了を初期開発の前提にしない。
- 接続対象の詳細と観測結果は [初期利用環境](初期利用環境.md) に記録する。認証情報の秘密値は文書に残さず、Router内では暗号化保存する。

## 3. 残る設計・検証事項

基本方針の再承認は不要。API、Registry変更、再起動、認証、技術構成、バックアップは実装し、[実装設計](実装設計.md) と [運用手順](運用手順.md) に具体化した。

| 項目 | 残る実機確認・後続作業 |
| --- | --- |
| 長文・処理能力 | 開発サーバでは120,020入力トークンと同時実行1・2・4を測定済み。継続的な多人数利用や異なるモデルは別途測定 |
| 試験 | 初回実機測定はアプリ経由で実施。研究室の実際のワークロードで追加測定し、管理者がCapacityを調整する。現状は暫定1 |
| ハードウェア監視 | 開発ホストのExporter接続と履歴表示は完了。他ホストは追加時に設定 |
| 配備 | Docker Composeで常駐化済み。学内公開先とTLS終端は配備先決定後に設定 |
| 後続環境 | GPUサーバAは登録済み。変更後の上流モデルと登録モデルの一致・実推論を確認する。GPUサーバBとOllamaは後続対応 |
| GuideLLM | 公開HFデータ取得、全方式の実GPU測定、新エンジンでの120k長文・長時間生成は未検証 |
| 健康状態 | 登録モデル不一致もEndpoint不健全判定に含む。通信状態とモデル状態の独立管理は未実装 |

構造化出力、旧Completions、Embeddings、Responsesは初回必須範囲に追加していない。開発サーバのtool callingは通常／Streamingとも実機確認済み。
